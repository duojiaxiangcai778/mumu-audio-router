# 2026-11-04 单实例失效修复（v1.3）

## 目标

用户反馈：v1.2 在**只开一个 MuMu 实例**时完全失效（只对开两个实例有效）。
这轮不只修「单实例」，连 v1.2 没暴露的根因一起挖掉。

## 症状

- 单开一个实例时，工具日志**一条动作都没有**（连退出日志都没有），工具进程活着，但焦点怎么切都不静音不恢复。
- 11-03 / 11-04 的 `router.log` 里多次启动记录后全是空白。

## 排查过程

### 1. 先看日志和现场

`router.log` 最后几次记录：只有启动行、之后零动作。
实测现场（单实例 MuMuNxDevice PID=16500，标题「1」，在前台）：

```
fgHwnd=0x140FB2 fgPid=16500 rootPid=16500 title=[1]
pid=16500 (MuMuNxDevice) state=1 vol=1.00 mute=True
```

**实例会话确实是 mute=True** —— 但用户说没生效。矛盾点：可能是静音了没恢复（上次异常退出残留），或者工具根本没在工作。

### 2. 关键一击：看工具进程的 SessionId

```powershell
Get-Process MuMuAudioRouter | Select Id,SessionId,ProcessName
```

结果 **SessionId=0**！而桌面在 SessionId=1。

> Session 0 是 Windows 的服务会话，从 Vista 起被隔离：没有用户桌面、没有用户音频设备。

于是：
- `GetForegroundWindow()` 在 Session 0 恒返回 0 → 工具永远认为「无前台实例」
- Session 0 枚举不出用户音频会话 → 想静音/恢复都没对象
- 进程活着但不干活，日志只有启动行（`Apply` 的 `instCount==0` 两处直接 `return`，什么都不写）

同时 `ParentProcessId` = WmiPrvSE.exe —— 确认是 **WMI 消费者**拉起来的，WMI 消费者天然跑在 Session 0。

**结论：v1.2 的多实例"能用"是因为当时手动双击（Session 1），WMI 自动拉起从来就没真正work过。**

### 3. 顺带发现：WMI 消费者写错了

原安装脚本用：

```powershell
$consumer = Set-WmiInstance ... -Arguments @{ CommandLineTemplate = "..." ; Arguments = "..." }
```

`CommandLineEventConsumer` **根本没有 `Arguments` 属性**（那是 `ActiveScriptEventConsumer` 的），会报 `Set-WmiInstance : Not found`。原来的写法把参数全塞进 `CommandLineTemplate` 才勉强成立。

## 修法

### A. 计划任务桥（核心）

安装时创建交互式计划任务：

```powershell
schtasks /create /tn MuMuAudioRouter /tr "E:\MuMu实例音频路由\MuMuAudioRouter.exe" \
  /sc once /st 00:00 /ru Administrator /it /rl LIMITED /f
```

- `/it` + `Interactive only` = 只在用户登录的交互会话里跑 → Session 1
- `schtasks /run /tn MuMuAudioRouter` 手动触发可当场拉起

WMI 消费者改为只执行：

```
C:\Windows\System32\schtasks.exe /run /tn MuMuAudioRouter
```

实测（2026-11-04 15:36）：伪造 MuMuNxMain 进程启动事件 → 工具被拉起，日志 `Session=1`，`[焦点变化] 实例 PID=16500「1」 出声`。

### B. exe 自身兜底

`Program.Main` 在抢 mutex 之前先查：

```csharp
if (SafeSessionId() == 0) { Log("运行在 Session 0 ... 重新拉起"); RelaunchInUserSession(); return; }
```

`RelaunchInUserSession()` = `schtasks /run /tn MuMuAudioRouter`。

### C. 单实例跟随开关

根因虽然修掉了（Session 1 下单实例本来就会跟随），但用户明确要「单实例也生效」且要能选择，所以加了配置 + 菜单：

- `router.json` 新增 `singleInstanceFollow`（默认 true）
- `Config.Save()` 把设置写回文件
- `TrayContext` 菜单「单实例时也跟随（只开一个实例也生效）」勾选项
- `Apply` 里：

```csharp
bool bypass = instCount == 1 && !_cfg.SingleInstanceFollow;
bool shouldSound = bypass ? true
                : targetRoot < 0 ? !MuteWhenNoInstanceFocused
                : owner == targetRoot;
```

bypass 时日志写「只有 1 个实例且单实例跟随已关闭 → 保持有声」。

### D. 可观测性

- 启动日志：`=== 启动 v1.3 === ... Session=1`
- `Apply` 两处静默 `return` 改为 `QuietLog()`（30 秒限频），无前台/无实例时日志有痕迹

## 已知坑（下次别再踩）

1. **WMI 消费者 = Session 0**。任何需要桌面/音频/窗口的东西都不能直接被 WMI 拉。用计划任务 `/it` 桥接。
2. `CommandLineEventConsumer` 没有 `Arguments` 属性，参数全写 `CommandLineTemplate`。
3. `schtasks /create` 容易报 "已存在"（坑：`/f` 要放最后，且 `/tr` 值含空格时必须整体加引号；PowerShell 里用双引号包单引号）。
4. PowerShell 改含中文的脚本**必须显式 UTF-8 读写**：用 `[System.IO.File]::WriteAllText($p, $c, New-Object System.Text.UTF8Encoding($true))`，否则默认 ANSI（GBK）→ mojibake（v1.2 的教训）。
5. `$pid` 是 PowerShell 只读自动变量，脚本参数不要用 `$pid`。
6. 强制切前台要 `AttachThreadInput(currentThread, foregroundThread, true)` + 模拟一次 ALT 键，否则 `SetForegroundWindow` 被前台锁拒绝（返回 True 但实际没切）。
