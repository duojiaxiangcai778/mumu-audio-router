# 2026-11-07 前台实例却还是静音（v1.3.1）

## 目标

用户反馈：**木木（MuMu）实例就在前台、游戏内音量 100%，但 Windows 系统音量合成器里它的声音还是静音状态**，
工具没把音效放开。上一版 v1.3（11-04）交付后第一次报这个症状。

## 症状与现场

- 前台窗口：`fgHwnd=0x40A60 fgPid=35468 (MuMuNxDevice) 标题「mumu-日服」`，只有 1 个实例。
- `router.log` 最新一条：`[焦点变化] 实例 PID=35468「mumu-日服」 出声` —— 工具**自己认为**已经放开了。
- 实测会话（`tools/diag_sessions.ps1`）：

```
pid=35468 (MuMuNxDevice) state=1 vol=1.00 mute=True
```

**mute=True** —— 和日志矛盾：工具说「出声」，系统里却还是静音。

## 排查

### 1. 先看日志细节：所有「出声 / 全部静音」都没有 `| 恢复:` / `| 静音:` 后缀

`Apply` 只有真的调了 `SetMute` 才会加这个后缀。后缀全缺 = **工具从头到尾一次都没真正动过会话**，
一直在「假动作」空转。

### 2. 读源码，找到自锁逻辑

`MuteAndRemember(s)`：

```csharp
if (!_saved.ContainsKey(s.Key))
    _saved[s.Key] = new SavedState { Volume = s.Volume, Mute = s.Mute };  // ← 把“当前已静音”当成原状
if (s.Mute) return false;      // 已经静音 → 不动作（也就不打日志）
s.Vol.SetMute(true);
```

`RestoreIfSaved(s)`（该出声时调用）：

```csharp
if (!_saved.TryGetValue(s.Key, out st)) return false;
if (s.Mute != st.Mute) { s.Vol.SetMute(st.Mute); acted = true; }  // ← 照“原状”还原
_saved.Remove(s.Key);   // 即使什么都没做也删掉记录
```

于是只要某个会话在**工具第一次看到它之前就是静音**：

1. `MuteAndRemember` 把 `Mute=true` 记成「原始状态」；
2. 之后每次该出声 → `RestoreIfSaved` 按「原状」还原成静音（本来就静音，连动作都省了）；
3. 记录被删掉，下一轮又按当时状态（静音）重新记一遍 —— **永久锁死**。

### 3. 为什么「会话一起来就是静音」是必然而不是偶然

Windows 把**每个应用的音量/静音**持久化在
`HKCU\Software\Microsoft\Internet Explorer\LowRegistry\Audio\PolicyConfig\PropertyStore`。
本工具上一轮把 MuMu 静音过 → 下次 MuMu 新建音频会话时**继承静音**。
所以用户每次都可能撞上「一启动就是哑的，工具还说它已经出声」。

### 4. 顺带发现：焦点抖动会把正在玩的实例静音

日志里大量成对的 `出声 → 1~5 秒后 无前台实例 → 全部静音`。`OnForegroundTick` 只比较 HWND 变化、
100ms 轮询，输入法候选框 / 气泡 / 通知这类**一闪而过的窗口**也会被当成「切走了」，立刻静音。

## 修法（v1.3.1）

1. **删除自锁**：新增 `EnsureSound(s)` 取代「还原记忆里的静音」——
   该出声就**无条件 `SetMute(false)`**，只还原本工具改过的音量。
   `MuteAndRemember` 里补 `s.Mute = true;` 更新本地缓存。
2. **`MassRestore`（暂停 / 退出 / 全部恢复）也强制放开实例静音**，不再依赖 `_saved` 记录，
   避免旧逻辑漏记 → 退出后还是哑的。
3. **焦点防抖** `debounceMs`（默认 250ms，可配 0~3000）：
   新前台窗口要稳定 250ms 才动作；关键点是**中途又变回原窗口就丢弃候选**，
   瞬态窗口不会再触发静音。
4. 启动清理 `ResetAllInstanceMute()` 保留（本次实测它确实清了残留静音：
   `启动清理：取消残留静音 PID=35468`）。

## 改动文件

- `src/MuMuAudioRouter.cs`
  - 头部注释、`AssemblyFileVersion/AssemblyVersion` → **1.3.1.0**，启动横幅 `=== 启动 v1.3.1 ===`
  - 新增 `EnsureSound()`；`RestoreIfSaved()` 保留给「非实例会话（PID 复用）」用
  - `Apply()` 的 shouldSound 分支改调 `EnsureSound()`
  - `MassRestore()` 增加实例会话强制解除静音（并顺带重建 `_map`）
  - `OnForegroundTick()` 加防抖；新增字段 `_pendingFg` / `_pendingSince`
  - `Config` 新增 `DebounceMs = 250`（`Load` / `Save` / `router.json` 同步）
- `router.json`：加 `"debounceMs": 250`
- `MuMuAudioRouter.exe`：重新编译（39.5KB，文件版本 1.3.1.0）
- `install-autostart.ps1` / `uninstall-autostart.ps1` 的 mtime 会变成进程启动时间——这是
  `ScriptWriter.EnsureScripts()` 每次启动重写的，不是手改，不用当漏记。

## 遗留 / 提示

- 「切到聊天窗口 → MuMu 静音」是设计行为（`muteWhenNoInstanceFocused` + 单实例跟随）。
  不想这样就托盘菜单关掉「无前台实例时全部静音」，或关掉「单实例时也跟随」。
- 仍然只处理默认播放设备的会话（多声卡同时输出未覆盖，与 v1.0 一致）。
- 若 MuMu 后续把音频改成跨进程共享服务，需要重新适配。
