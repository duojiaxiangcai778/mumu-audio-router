# 2026-11-07 只做开关、不碰音量（v1.3.2）

## 目标

用户要求：**这个工具只负责“开关（静音/出声）”，不要再把音量调到 100%**。
音量他已经手动在系统音量合成器里设好了，MuMu 一开就是 100%，工具不需要去“开成 100”。

## 现场核对（先怀疑“是不是真在写音量”）

- 源码全量搜 `SetVolume` / `SetMasterVolume` / `Volume`：v1.3.1 只有两处写音量，
  都在“还原”路径里，没有任何一处把音量顶到 1.0 的代码。
- 但**还原路径足以造成“他非要给我调成 100%”的观感**：
  1. `MuteAndRemember()` 静音时把当时的音量存进 `_saved[s.Key].Volume`；
  2. `EnsureSound()`（该出声时）比对 `s.Volume != st.Volume` → `SetVolume(st.Volume)`。
  3. 于是：**工具把它静音 → 你在静音期间把音量调低 → 切回实例，工具把音量“还原”成它记下的旧值**。
     反过来也成立：静音期间你调高，它也会给你改回去。用户看到的“又变 100%”就是这条。
- 另有一处 `RestoreIfSaved()`（非实例会话/PID 复用）也会 `SetVolume(st.Volume)`。
- 结论：不需要继续纠结“到底谁调的”，**把音量写入能力整体删掉**，从结构上保证它只会 `SetMute`。

## 改动（v1.3.1 → v1.3.2，版本号 1.3.2.0）

改动文件：`src/MuMuAudioRouter.cs`

1. `AudioSession` 删掉 `public float Volume;` 字段（不再读音量）。
2. `AudioApi.Enumerate()` 不再 `GetMasterVolume`，只 `GetMute`。
3. `AudioApi.SimpleVolume` **删掉 `SetVolume()` 方法**——类里只剩 `SetMute()`，
   编译期就杜绝“再有人顺手写音量”。`ISimpleAudioVolume` 接口声明保留（vtable 顺序必须完整）。
4. `SavedState` 只留 `public bool Mute;`（不再记忆音量）。
5. `MuteAndRemember()` 只记 `Mute`。
6. `EnsureSound()` 删掉音量比对/还原整段，只做「有静音就清掉」+ 清 `_saved` 记录。
7. `RestoreIfSaved()` 删掉音量还原，只还原静音。
8. 头部注释、文件版本/程序集版本 → `1.3.2.0`，启动横幅 `=== 启动 v1.3.2 ===`。

新增/沿用工具：

- `tools/session_volume.ps1`（新增）：按 PID 读/写某个音频会话的音量与静音，用来复验“工具不碰音量”。
  注意：参数名是 `-ProcessId`（`$Pid` 是 PowerShell 只读自动变量，不能用），文件必须存成 **UTF-8 带 BOM**，
  否则 `powershell -File` 按 ANSI 读会把中文注释读坏、解析报 `Unexpected token ')'`。

## 说明 / 遗留

- 现在**工具只在两个地方动音频接口**：`SetMute(true/false)`。
  音量完全归用户，改完不会被工具覆盖。
- 静音期间改音量仍然照做（工具不管音量），切回来音量还是你设的值。
- 若哪天 MuMu 自己把会话音量重置成 100%（这是 MuMu/Windows 行为，不是本工具），工具也不会去纠正——
  按用户要求，**音量的事不归它管**。
